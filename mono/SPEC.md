# 「モノに生まれたら」モノの作り方（説明書）

ブラウザゲーム「モノに生まれたら」に、新しいモノを追加するための説明書。
プレイヤーは身の回りのモノとして生まれ、統計データにもとづく一生を見届ける。ときどき「どうしたい？」と聞かれ、選んだ願いで行き先が変わる。

**お手本**：`things/coin.js`（1円玉）と `things/bottle.js`（ペットボトル）。書き方に迷ったら、必ずこの2つを読むこと。
**遊んだ人の感想**：「めっちゃ面白かった」「選択肢によっては、もっと長くてもいい」「毎回同じ質問が出るのはつまらなかった」（→ 今は直してある）。この面白さを、どのモノでも出すのが目標。

---

## 1. ファイルのルール

- 1つのモノ ＝ 1つのファイル：`things/<id>.js`。中で `MONOS.<id> = { ... };` を作る。`<id>` は英小文字と数字だけ（例: `bill10000`, `smartphone`）。
- 自分のグループのイラスト部品（新しいシーン・主人公の絵の共通部品）は `things/_art_<担当コード>.js` に書く（例: `_art_c1.js`）。
- **ファイルの中身は全部 `(() => { "use strict"; ... })();` で包む**。包まないと、ほかの人のファイルと関数名がぶつかる。外に出してよいのは `MONOS.xxx = …`、`SCENES.xxx = …`、`ART.<担当コード> = {…}` だけ。
- 新しく作るシーンの名前には、必ず担当コードを頭につける（例: `c1_shop`, `d2_classroom`）。ほかの人とぶつからないように。
- `core.js`・`index.html`・ほかの人のファイル・`things/coin.js`・`things/bottle.js` は**書きかえない**。`git commit` / `git push` もしない（まとめ役がやる）。
- 読み込む順番：`core.js` → `things/_art_*.js`（名前順）→ `things/<id>.js`。だから `<id>.js` からは `ART.<担当コード>` を使えるが、`_art` ファイルから `MONOS` は使わない。

### core.js にある、使ってよい道具
| 名前 | 使い方 |
|---|---|
| `rand(a,b)` `rint(a,b)` | a〜b の乱数（小数・整数） |
| `pick(配列)` | ランダムに1つ |
| `wpick([{w:重さ,...},...])` | 重さつきで1つ選ぶ |
| `PREFS` | 47都道府県の名前 |
| `face(mood)` | 顔の絵（原点中心、だいたい横±16・縦±12）。mood は `happy` `neutral` `sad` `surprise` `sleep` |
| `sparkle(x,y,s)` `cloud(x,y,s)` `miniBottle(x,y,色,s)` `otherCoin(x,y,r,色,線の色,穴)` | 小さな絵の部品 |
| `SCENES` | 共通のシーン（下の一覧） |
| `BOTTLE_COLORS` | ペットボトルの中身の色 |

## 2. モノのデータの形

```js
(() => {
  "use strict";
  function hero(c, mood) { return `<g>…SVG…${face(mood)}…</g>`; } // 主人公の絵

  MONOS.bill10000 = {
    name: "一万円札",                 // 画面に出る名前
    group: "お金",                    // お金 / 容器 / 電化製品 / 身の回り / その他
    hero,                             // 主人公の絵の関数 (c, mood) => SVG文字列
    time: "year",                     // 一生を数える単位："year"（○年目）か "day"（○日目）
    condLabel: "きれい度",            // 状態の数字の名前（ピカピカ度・バッテリー・元気 など）
    odds: "113億",                    // 「○○分の1」の○○の部分（調べた数字から）
    oddsText: "いま世の中にある一万円札は、約113億枚。あなたはその中の1枚です。",
    sources: [{ n: "日本銀行「銀行券の発行・流通・還流」", u: "https://..." }], // 📊で使った出典
    owners: ["会社員", "おばあちゃん", ...],  // 持ち主の候補（5人以上。{owner} に入る）
    init(c) { ... },                  // 一生の始めの準備（なくてもよい）。c.v.xxx に決めた言葉を入れる
    birthText: (c) => `…で生まれた。`, // 最初の一文
    start: "factory",                 // 最初の場所
    aging: 0,                         // 1単位の時間ごとに状態が減る量（なくてもよい）
    places: { ... },                  // 場所（下を参照）
    ends: { ... },                    // 生まれ変わりの上限に達したときの結末（rebirth を使うときだけ）
    onRebirth(c) { ... },             // 生まれ変わったときの準備（rebirth を使うときだけ）
    shareStart: (c) => `…として生まれ`, // シェア文の書き出し（なくてもよい）
    year: (c) => …, ageLabel: (c) => …, meta: (c) => …  // 画面上部の表示（なくてもよい。ふつうは書かない）
  };
})();
```

### c（一生の状態）
`c.t` 経過時間（time の単位）、`c.gen` 何代目、`c.owners` 持ち主の数、`c.km` 旅した距離、`c.cond` 状態（0〜100）、`c.fill` 中身（0〜1、使いたければ）、`c.v` 文章に入れる言葉、`c.flags` 自由な目印、`c.startYear` 生まれた年（2026）。
文章の中の `{名前}` は `c.v.名前` に置きかわる。いつでも使えるのは `{owner}`（今の持ち主）、`{pref}`（生まれた県）、`{pref2}` `{shop}` `{wish}` `{cause}` `{outing}` `{beach}`（毎回ランダム）。ほかの言葉は `init` や場所の `init` で `c.v.xxx = …` と決めてから使う。

### 場所（places の中身）
```js
wallet: {
  scene: "wallet",                         // シーンの名前（SCENES にあるもの）
  label: (c) => `${c.v.owner}の財布の中`,   // 画面の「📍」に出る場所の名前（文字列か関数）
  stay: [0.05, 1.6],                       // この場所にいる時間（time の単位）[短い, 長い]
  n: [1, 3],                               // 出来事をいくつ見せるか [少ない, 多い]
  events: [                                // 出来事（ここからランダムに n 個。同じものは一生で1回だけ）
    { t: "文章", m: "happy" },             // m: 顔
    { t: "📊になる文章", f: "財務省", m: "neutral" },  // f: 出典の短い名前 → 📊がつく
    { t: "…", c: (c) => 条件, w: 3 },      // c: 出る条件 / w: 出やすさ（ふつう1）
    { t: "…", e: { km: [200, 900], cond: -5, owner: true, who: "…", flag: "charm", fill: -0.5 } }, // e: 変化
    { t: "…", r: true }                    // r: 何回出てもよい（ふつうは1回だけ）
  ],
  choices: [ /* 質問（下を参照）*/ ],
  next: [                                  // 次の行き先（重さで選ばれる）
    { to: "register", w: 3, t: "移動するときの文章", m: "happy", e: { owner: true } },
    { to: "collector", w: (c) => (c.flags.error ? 0.7 : 0), t: "…" }   // w は関数でもよい
  ]
}
```
- 1つの場所には `next`（次へ進む）・`end`（ここで一生が終わる）・`rebirth`（生まれ変わる）の**どれか1つだけ**を書く。
- 結末の場所：`end: { key: "lost", title: "押し入れの眠り姫", t: "最後の文章", short: "シェア用の短い文（〜した、で終わる）", m: "sleep" }`
- 生まれ変わり：`rebirth: { max: 3, t: "生まれ変わったときの文", f: "出典", end: "melted" }` → `ends.melted` が上限のときの結末。`onRebirth(c)` で中身を入れかえる。
- `e.owner: true` で持ち主が変わる（`who` で名前を指定できる。`who` の中で `{owner}` を使うと前の持ち主）。

### 質問（choices）と「もう少しがんばる？」（escape）
```js
choices: [
  { q: "{owner}が、旅行の計画を立てている。",   // 状況＋問いかけ
    c: (c) => 条件,                              // 出る条件（なくてもよい）
    a: [                                         // 選択肢は2〜3個
      { l: "ついていきたい！", t: "結果の文章", go: "travel", m: "happy" },  // go: すぐその場所へ
      { l: "家で留守番したい", t: "…", b: { drawer: 3 }, m: "neutral" },     // b: 次の行き先の出やすさを何倍にするか
      { l: "のんびりしたい", t: "…", extend: 2 },                             // extend: この場所に長くいる（出来事が2つ増える）
      { l: "キラッと光ってみせる", p: 0.5,                                    // p: 成功する確率
        ok: { t: "成功したときの文", go: "crow", e: { km: [1, 8] } },
        ng: { t: "失敗したときの文", m: "sad" } },
      { l: "…", t: "…", dt: [10, 30] }                                        // dt: 時間がたつ
    ] }
],
// end のある場所にだけ書ける。結末の直前に聞く（1回の一生で2回まで）
escape: { q: "押し入れの奥で、もう何年も眠っている。", a: [
  { l: "このまま眠りにつく" },                   // 何も書かない＝そのまま結末へ
  { l: "見つけてもらえるまで待つ", p: 0.55,
    ok: { t: "…見つけてくれた！", go: "wallet", dt: [10, 30], e: { owner: true } },
    ng: { t: "だれも来なかった。" } }
] }
```
- 1回の一生の中で、**同じ質問は二度と出ない**（仕組みが自動でそうする）。だから**質問の数が多いほど、毎回ちがう体験になる**。1つの場所に1〜4個。
- 着いた場所に質問があれば、80%の確率で1つ出る（1回の一生で12個まで）。
- 選択肢は「〜したい」「〜する」という**モノの願い**の形。どちらを選んでも**ちゃんと違うことが起きる**ようにする（ただ文章が違うだけ、を減らす）。
- 「のんびり」「ゆっくり」「まだ終わりたくない」系の選択肢（`extend`、`escape`の成功）は、一生が長くなる。遊んだ人は「選び方しだいで長くなるのがいい」と言っている。
- 成功・失敗（`p`）のある選択肢は、ドキドキするので各モノに5個以上入れる。

## 3. 量と中身の目安（チェックで注意が出る）

1つのモノにつき：
- **場所 12個以上**、**出来事 40個以上**、**質問 18個以上**（escape も数える）、**結末 6種類以上**。
- 結末のうち3つ以上に `escape` をつける。
- 一生の長さは、そのモノの本当の寿命に合わせる（車なら十数年、割り箸なら数日、など）。「生まれ変わり」が自然なモノ（リサイクルされる素材、溶かされるお金など）は `rebirth` を使ってよい。
- **数万通り**の一生にしたいので、行き先の分かれ道を多くし、持ち主・場所・出来事の言葉をランダムにする（`c.v` や `{pref2}` `{shop}` など）。

## 4. 数字（📊）のルール — とても大事

- 担当の調査ファイル（`/tmp/claude-0/-home-claude/2d2045b1-6ecf-5109-bdff-6c6ae9b2104e/scratchpad/data/*.md`）に**書いてある数字だけ**を使う。数字を作らない、覚えている知識で数字を書かない。
- 📊（`f:`）をつけてよいのは、調査ファイルで【確認】か【推定】になっている事実だけ。【推定】のときは文章で「〜と言われている」「約」などをつけて言い切りすぎない。
- `f:` には出典の短い名前（「日本銀行」「環境省」「内閣府の消費動向調査」など）。使った出典は `sources` に URL ごと入れる（URLは調査ファイルにあるものだけ）。
- 行き先の重さ（`next` の `w`）は、データがあれば実際の割合に合わせる（例：回収率91.9% → 回収92：それ以外8）。コメントで「〜の割合にもとづく」と書く。データがなければ、ありそうな重さでよい（演出）。
- `odds`（○○分の1）は調査ファイルの数字から。年間の数か、今ある数か、`oddsText` でわかるように書く。数字がまったくないモノは、`odds: "数えきれない"` のようにして、`oddsText` に「はっきりした統計はないけれど…」と正直に書く。
- 📊のない出来事は「演出」。統計っぽい言い方（「○%の」など）をしない。

## 5. 文章のルール

- 日本語。**小学生でも読める**やさしい言葉。一文は短く。むずかしい漢字や専門用語は、言いかえるか、すぐ後に説明する。
- モノの目線で、過去形（「〜した。」「〜された。」）。少しユーモアを入れる。モノの気持ち（うれしい・こわい・ねむい）を入れる。
- 実在の会社名・商品名・ブランド名・人名は出さない（「交通系ICカード」「ゲーム機」など一般名で）。報道された事実でも、会社名は出さない。
- 人がケガをする・死ぬ・犯罪・こわすぎる話はしない。悲しい話はやさしく。下品な話もしない。政治の話もしない。
- 持ち主（owners）は「部活帰りの高校生」「近所のおばあちゃん」のような役割で書く。決めつけ・からかいになる書き方はしない。

## 6. イラストのルール

- 画面は `viewBox="0 0 360 200"`。**明るいパステルのフラットな絵**（ドット絵にしない）。モノの目線で、まわりの物が大きく見える感じ。文字はできるだけ入れない（入れるなら短い一般名詞だけ。ブランド名はダメ）。
- **主人公（hero）**：原点 (0,0) が中心。**横 −45〜45、縦 −62〜52 の箱に収める**（ペットボトルがちょうどこの大きさ）。体のどこかに `face(mood)` で顔をつける（必要なら `translate`・`scale` で大きさを合わせる）。そのモノだと一目でわかる形と色にする。`c.cond`（状態）で色をくすませる・`c.v` で色を変える、なども歓迎。
- **シーン**：`SCENES.c1_shop = (c) => ({ x: 180, y: 110, s: 0.7, r: 0, bg: \`…SVG…\` })`。`x,y` は主人公を置く位置、`s` は主人公の大きさ、`r` は回転（寝かせたいとき）。主人公が隠れないように、まわりを描く。
- まず共通のシーンを使い、合わないところだけ新しいシーンを作る。1つのモノに、**そのモノらしい場面のシーンを3つ以上**は新しく作るとよい（例：スマホなら家電量販店・教室の机・中古ショップ）。

## 7. チェックのしかた（必ずやる）

```
cd /home/claude/games/mono
node tools/validate.js <id1> <id2> ...        # 静的チェック＋60回のシミュレーション
node tools/validate.js <id> --lives=150       # 回数を増やす
node tools/shot.js <id> /tmp/…/shot-<id>.png  # 全シーンの絵を1枚に並べた画像 → Read で見て確かめる
```
- **エラー0件**にする。注意（⚠）もできるだけ0件にする。
- シミュレーションの結果で、結末がかたよりすぎていないか（1つの結末が半分以上なら見直す）、一生の長さが自然かを見る。
- 絵は必ず `shot.js` の画像を自分の目で見て、はみ出し・重なり・主人公が見えない、を直す。
